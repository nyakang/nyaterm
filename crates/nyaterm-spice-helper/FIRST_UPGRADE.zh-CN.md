# Windows 便携版首次升级到 SPICE 版本

首次提供 SPICE 的版本采用手动便携迁移。旧版内置更新器的 ZIP 文件清单是编译进
程序的，无法识别新增的 helper 与 `spice/` 运行库；不要依靠旧版内置更新完成这次迁移。
发布说明应附上本说明和对应架构的完整便携 ZIP。此后的更新使用新版更新器。

1. 在旧版中通过应用的备份功能导出一份 `.nya` 备份，并妥善保存备份密码。
2. 完全退出旧版 NyaTerm，确认连接和后台任务已结束。
3. 下载并校验本次发行的完整 Windows x64 或 ARM64 便携 ZIP，解压到一个新目录。
   保留包内所有 helper、`spice/`、`conpty/`、`adb/` 和 Android 库，不混用两种架构的文件。
4. 将旧便携目录的整个 `data/` **复制**到新便携目录，替换新包自带的空数据占位目录。
   保留旧程序目录及其原始 `data/`，不要让两份程序共享同一个活动数据库。
5. 启动新目录中的 `NyaTerm.exe`，确认已有连接、凭据、设置正常，再验证 SPICE。
   原有连接引用的外部密钥、脚本等文件应保持在原路径。
6. 确认迁移成功后，将快捷方式改为指向新目录。旧目录和备份可保留到验收结束。

若新版本不能正常启动，退出新版本后，用旧目录的程序及其原始数据回退。不要用旧程序
直接打开已被新版本写入的数据。需要重新迁移时，通过应用支持的备份恢复功能操作。

上述步骤不改变安装版更新流程，也不要求迁移 Linux/macOS 配置。Ubuntu 20.04 兼容包
继续使用其独立的手动升级渠道。

# SPICE 手动验收记录

此清单用于真实虚拟机与发布包验收。自动化原生库探针、模拟服务器和 CPU
基准不能代替以下结果。没有测试的项目记为“未验证”，失败的项目保留复现条件。
跨平台鼠标捕获已有实现，真实设备仍待验收；系统保留组合键可使用“发送组合键”菜单。
实现范围与自动化证据见 README；未执行的实机项目不应当作已通过。

## 环境记录

每次记录 NyaTerm 提交、包类型、宿主系统及架构、CPU/GPU、显示缩放、网络往返
延迟、QEMU/Proxmox 版本、客体系统、客体 SPICE agent 版本。不要附带 `.vv`
原文件、密码、票证、剪贴簿正文或含用户数据的录屏。

至少覆盖 Windows x64/ARM64、macOS x64/ARM64、Linux x64/ARM64；Linux 分别记录
X11 和 Wayland。ARM64 交叉编译成功不能当作 ARM64 实机通过。macOS 在较新
系统上成功也不能证明符合应用的 macOS 12 最低版本要求。

macOS 运行库已采用固定源码构建，准备和最终打包均拒绝最低版本高于 12.0 的
Mach-O 库及插件。完整源码构建配方已在 Linux/focal 上执行并通过库加载和 TLS
探针；这不是 macOS 原生编译结果。macOS 验收还需在干净机器上检查运行库加载、
签名、真实画面、音频设备及鼠标捕获，并至少覆盖 macOS 12。

准备两种客体：安装并运行 SPICE agent 的桌面系统，以及没有 agent 的启动菜单、
安装器或 BIOS 控制台。后者主要检验相对鼠标和基础键盘，不能要求剪贴簿或文件传送。

## 连接与安全

| 操作 | 应有结果 |
| --- | --- |
| 手动创建 TLS 连接，关闭应用后重开 | 普通连接设置保留，密码仍通过原有加密凭据管理 |
| 正确、错误密码分别连接 | 成功或明确认证失败；日志不含密码 |
| 使用正确 CA、错误 CA、错误证书主体验证 | 正确配置成功；错误配置拒绝连接，不能回退明文 |
| 仅启用 TCP；仅启用 TLS；同时启用两种端口 | 与所选 TLS 策略一致；禁用必需端口不能保存 |
| 通过已有 SSH 跳板或代理连接 | 显示、输入和后续通道都使用所选路由 |
| 下载 Proxmox `.vv` 并在新建菜单中打开 | 显示临时连接确认，连接后不进入保存列表、同步或启动恢复 |
| 使用过期 `.vv` | 提示重新获取文件；不循环重试旧票证 |
| Windows 勾选/不勾选删除来源文件；导入期间修改来源文件 | 仅在用户选择且原文件未变化时按文件句柄删除；变化的文件保留 |
| Linux/macOS 导入 `.vv` | 来源删除开关不可用，并提示导入后手动清理；原文件保留 |
| 导入含 USB、智能卡、目录共享选项的文件 | 明确列出未支持选项；不会自动访问本机设备 |
| 安装后在文件管理器中对 `.vv` 使用“打开方式”选择 NyaTerm | 进入同一导入确认流程；不改变已有默认查看器 |
| 稳定版与预览版同时安装，卸载其中一个 | 另一个版本及其他查看器的文件关联保留 |

`.vv` 往往携带短期密码或代理票证，不能把它当作长期连接配置保存。
“TLS CA 留空”使用随包 CA 集合，不代表使用宿主操作系统的证书存储。

## 显示、输入和生命周期

| 操作 | 应有结果 |
| --- | --- |
| 改变窗口尺寸、最大化、跨不同 DPI 的显示器移动 | 图像比例正确；动态分辨率有 agent 时生效；无裁剪错位 |
| 客体设置多个显示器，切换可见显示器 | 对应画面、指针及输入坐标一致，不混入旧帧 |
| 客体快速滚动文本、播放视频、更新小区域 | 不残影、不乱序，不持续积压旧画面 |
| 无 agent 控制台中点击画面，连续移动鼠标越过窗口边缘 | 持续接收相对位移；按 Shift+F12 释放，可再次点击捕获；X11 隔离探针已通过，真实桌面仍待验证 |
| 相对模式中使用 AltGr、Ctrl+Alt 组合键 | 不误触发释放；释放快捷键仅为 Shift+F12 |
| Wayland 合成器不支持锁定/相对指针扩展 | 点击捕获时显示不可用提示，不能静默退回受屏幕边缘限制的坐标差值 |
| 按住修饰键/鼠标键后切标签、失焦、锁屏、关闭连接 | 客体不留下卡住的按键或拖动 |
| 测试数字区、方向键、功能键、左右修饰键和 Ctrl+Alt+Delete | 客体收到正确键；受宿主保留的组合键应有明确行为 |
| 从“发送组合键”选择 Alt+Tab、Windows/Super、Ctrl+Alt+F1～F12 | 客体执行对应快捷键，本机桌面不切换；只读或断开会话不可发送，菜单关闭后恢复画面焦点 |
| 在客体启用中文/日文输入法 | 物理键输入正常；宿主 IME 提交文字目前应引导使用客体输入法或剪贴簿 |
| 将连接隐藏 5 分钟后恢复 | 隐藏时降低后台负载，恢复后及时取得完整画面 |
| 连接中断、断网、关闭窗口、终止辅助进程 | 状态明确；普通连接按设置重连；无遗留辅助进程 |

## agent 功能

| 操作 | 应有结果 |
| --- | --- |
| 分别设置本机→客体、客体→本机、双向和关闭剪贴簿 | 只按允许方向同步；切换标签不会串入其他连接 |
| 复制多行文本、中文和含表情文本 | 无重复换行、乱码或无上限内存增长 |
| 发送单个文件、多个文件、Unicode 文件名；取消传送 | 内容与文件名正确，进度和取消状态可靠 |
| 传送时停止 agent、断网或客体磁盘满 | 给出失败状态；不能把失败显示为完成 |
| 播放客体音频、静音、恢复，切换本机输出设备 | 无持续噪音或累积延迟；静音后不残留旧音频 |
| 拔掉/禁用音频输出设备 | 画面与输入仍可用，音频错误不拖垮会话 |

当前不提供麦克风输入、USB 重定向、智能卡、持久目录共享或 Proxmox 虚拟机清单 API。
文件传送是用户显式选择文件后的发送操作。

## 配置、批量编辑与发布包

验证单独修改 TCP/TLS 端口、剪贴簿方向、静音及重连次数不会覆盖其他字段。
批量清空所有端口，或保持“要求 TLS”却清空 TLS 端口，应在任何数据写入前报错。
普通端点可以同步；票证、代理 URL 密码及未知扩展不能进入云端字段。

在没有系统 SPICE/GStreamer 开发环境的干净机器上安装正式包并连接。
安装路径包含空格与中文也应正常。确认 `spice` 目录不会因连接生成缓存文件。
便携升级失败后旧程序和完整运行库必须可恢复；成功后旧插件不应残留。
旧更新器不能安装新增运行库的 ZIP；首次发行采用 `FIRST_UPGRADE.zh-CN.md` 中的手动
便携迁移流程。验收时分别验证新目录迁移成功，以及保留旧目录和原始数据后的回退。

## 性能测量

使用相同客体、分辨率、内容、网络和电源模式，与当前使用的 SPICE 客户端比较。
分别记录静止画面、持续滚动、1080p 视频、4K 全屏变化和多显示器；预热后至少
记录 60 秒的宿主 CPU、辅助进程/主进程内存、网络吞吐、输入延迟和可见卡顿。
图像清晰度不同的结果不能直接比较性能。

现有 Windows x64（Ryzen 7 5700G）真实进程管道基准为：1080p 全帧平均 4.05 ms、
P95 4.50 ms；4K 全帧平均 18.26 ms、P95 23.46 ms；4K 中 256×128 脏区平均
0.064 ms、P95 0.094 ms。它只测转换、管道和消费端应用，未包含协议解码、网络、
GPUI/GPU 与音频，因此不能宣称实际帧率或端到端延迟。完整命令及其他基准见 README。

Linux x64/WSL 的三轮管道对照中，4K 全帧每轮平均耗时的中位数从 34.274 ms
降至 18.973 ms。优化只调整 helper 的输出管道容量至最多 1 MiB，受系统限制时
保留原容量。此结果同样不代表真实 Linux 桌面或客体的帧率，仍需按上表实测。

验收记录格式：`环境 / 操作 / 预期 / 实际 / 通过、失败或未验证 / 复现次数`。
